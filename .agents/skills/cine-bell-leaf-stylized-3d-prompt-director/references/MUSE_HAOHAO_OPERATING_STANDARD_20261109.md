## 2. Image/face and location anchors — strict precedence

**Source priority:** original owner-provided face source + SHA → verified pixel-exact isolated crop from that source → separately approved single-view angle/outfit → authored shot-specific first frame → text direction. An auto-generated expression or turnaround is NOT canon until owner + independent QC approve it.

- For every on-screen actor select **ONE primary isolated face/hero source**, then at most a *small necessary* set of relevant compatible body/angle/outfit references. The current 10 stored multi-panel portraits are ambiguous for video: isolate exact source crops *without changing facial geometry*, verify SHA/provenance, then replace/augment HaoHao's slot only after review. Do not treat a panel-containing sheet as a single character frame. No collage/3×3 grid in video output.
- Lock one outfit ID per scene and shot (for example Juno workshop vs school). If the shot crosses wardrobe continuity, solve the script/blocking or split shot before prompt. No duplicate body parts or cosmetic facial beautification.
- Location reference: choose one approved matching \`site_id/space_id/view_id\` and preserve window/door orientation, set topology, furniture and prop positions. When only the front view exists, an arbitrary reverse-angle shot is **HOLD_LOCATION_ANGLE**, never automatically mirrored or inferred as approved. Carry shot set topology into adjacent angles.
- First-frame step: render **one** full-bleed 16:9 independent 3D animated frame containing only visible canon actors and the desired initial pose. Check face at actual image pixels and distance, age, costume, contact/props, camera axis and architecture. Obtain recorded \`APPROVED_FIRST_FRAME\` with path+SHA before sending video. Do not claim Muse I2V will reproduce the exact first-frame pixels automatically.
- For \`ACTIVE TAGS FOR THIS SHOT: []\`, attach **no character image refs**. Attach only explicitly needed scene/location evidence, or none if a context-free background.
- **BUBU**: purple cat, ONE gold collar bell, permanently sparkling purple spiral tail. **BIX**: compact cute turtle-pangolin *mechanical robot, without any bell*. Never mix their props or silhouette.

## 3. Writing a high-quality 10-second Muse prompt

**External TXT contract, NEVER break:** one complete shot prompt on exactly ONE physical text line; between adjacent shot lines **exactly one empty line**; no headings, explanatory comments, markdown code fences or internal newline within a shot. Separate image and video TXT files, identical ordered shot IDs and active tags; one 16:9 image per shot (not a grid). Save a structured per-shot JSON/dialogue plan alongside for machine execution, not in those TXT lines.

**Causal ordering inside one-line video prompt:** \`SERIES/REV/S###\` → \`10.0s 16:9 24fps\` → \`ACTIVE TAGS + @names + source SHA/role\` → \`site/room + canonical time\` → \`style/outfit\` → \`framing/lens/eye-level + camera path\` → \`0–2 setup\` → \`2–7 purposeful acting\` → \`7–10 reaction\` → \`speaker/emotion/exact dialogue cue\` → \`realistic ambient sound in stylized 3D setting\` → short negative constraints. Keep prompt concise and *observable*, not adjective soup. Prefix must include an immutable screenplay revision ID (e.g. \`EP001_V22_S003\`) matching the actual locked source; never guess revision.

- One take, 10.0 seconds / 240 nominal frames @24fps, no hidden montage, cut, fake zoom-only, grid, live-action re-cast, random camera orbit or implausible fast-action physics. Animation is actual eye/face/hand/prop/body performance.
- Most conversations: medium close-up or medium shot at speaker eye height, 50mm-equivalent framing, calm motivated track/push, restrained mild depth of field. Intimate revelations: 65–85mm-equivalent close-up with visible lips; location reveal: 28–35mm-equivalent wide shot. Lens number guides composition, not verified lens optics. Camera crossing/180-degree axis must be motivated by true coverage.
- Daylight: clean D55 ~5500K and neutral shadow balance when Canon calls for day; no blanket warm yellow grade. Magical night uses actual locked source light.
- 0–2s: establish eye focus/prop/contact; 2–7s: one legible action or one short English A2 utterance; 7–10s: meaningful emotional reaction or story information. Adjust beats when needed but never change shot duration.
- For the first 15 seconds: S001 must create a real hook immediately, S002 reinforces/changes it by 15s, with no fake danger or early exposition. The episode-specific hook and shot timeline are authoritative.
- First-frame image prompt describes a static **initial** pose; video prompt describes **movement from that frame**. Avoid repeating a whole story outline, unrelated future characters or many incompatible actions.
- No subtitles/text baked by Muse: perform editable timed SRT/VTT overlay **after** confirming actual spoken audio; max two lines bottom safe margin, white with soft dark edge, do not cover lips/important hand motion. No claims that the model rendered perfect dialogue text.
- Request 4K detail as an aesthetic target only. \`ffprobe\` the actual output; 720p source can be sharpened/upscaled separately into labeled 3840×2160 delivery **without claiming native 4K**.

**ONE-LINE safe sample, not a permission to generate without refs:**

\`EP001_V22_S003, 10.0s, 16:9, 24fps; ACTIVE TAGS FOR THIS SHOT: [juno,bix]; @Juno @BIX @BellKitchen_Day; stylized original 3D CGI family animation, exact owner reference for Juno's young 13-year-old face and BIX's compact turtle-pangolin robot without a bell, matching approved Bell kitchen layout and Juno's selected canonical workshop outfit; child-eye medium two-shot, gentle stabilized 50mm-equivalent tracking shot, natural D55 morning daylight; 0–2s Juno watches BIX balancing toast, 2–7s Juno speaks the locked A2 line while BIX adjusts its claws, 7–10s BIX turns with a pleased reaction; physically motivated gestures and correct toast contact; English speech from Juno only, short expressive happy tone; subtle kitchen ambience; one continuous take, no cut, no additional person, no photorealistic people, no printed subtitles or storyboard layout.\`

**Example current dialogue from the existing EP001 recorded test (do not overwrite with unrelated text):** \`Dad, Bix can carry the toast now. I tested him yesterday.\`

## 4. Crucial HaoHao adapter — format, attachments, and voice

1. The *owner-facing* import TXT must stay one line per shot. BEFORE submission, an adapter must split that line into a **video visual brief** and **structured \`dialogue\` array** with immutable speaker-ID, exact English text, emotion, requested speed, per-shot reference file SHA and scene identity. Alternatively append a separate \`@Juno [happy]: "exact line"\` **at start of its own internal line** when passing \`voicePrompt\` to HaoHao. **Do not** place this line in the import TXT; do not promise the existing plain Studio \`submit\` automatically parses in-line dialogue.
2. \`ui/studio.js\` calls \`Compose.imagesFor\` and attaches **all** images for mentioned characters/location. The operator must inspect the shown attachment count and source roles. A non-authorized extra character reference or mismatched outfit → **HOLD_ATTACHMENT**, not submit. Private owner images should remain local, never pushed into public git.
3. \`engine/fixed-voice.js\` allows a single unique speaker+voice per converted task. Character aliases must match exact HaoHao studio names (e.g. \`@Juno\`; \`@BIX\` is a silent on-screen companion in Juno's speaking shot). If two different speakers must talk in a single 10s shot, split the *speech plan* or choose a separately verified multi-speaker workflow; never trick the one-speaker mapper.
4. The currently stored \`config/niches/slow_english_a2/voice_registry.json\` holds **audition candidates**, NOT 10 approved canonical reference WAVs. Load the latest registry dynamically; don't hard-code a deprecated EmotiVoice speaker ID. Test whether each part sounds its intended age/accent/emotion. Short controlled TTS sample accuracy doesn't prove ten-episode voice consistency.
5. The user's local HaoHao EmotiVoice preview tempo fix changed \`length_regulator(..., alpha=alpha)\`, allowing 0.7–1.3× TTS WAV pace control, but **NOT** control of Muse's generated speech timeline. Muse emits native speech and synchronized mouth movement; OpenVoice V2 swaps timbre without recomputing video lip motion. Treat \`voiceConverted: true\` as PROCESS COMPLETE only, not VOICE PASS or LIPSYNC PASS. The default saved \`voiceEmotion\` does not force the model's emotional performance.
6. Use exact one-speaker lines with age-appropriate performance, General American if actually approved, expressive-but-plain Slow English A2 and short timing. Aim roughly 110–145 spoken words/min (not an unconditional limit for laughter/whisper/gasp), 1–2 short sentences with an emotional pause; **verify measured speech rate** after generation. Prior sample previews measured 125–140 WPM but Muse output is separate.
7. When speech ASR omits, duplicates or distorts \`Bix\` or names, retry from the source with corrected diction/audio direction or record manual review; do not fake transcript success. Face/voice/viseme audits must examine actual media, not just task metadata.
8. Do not send any API key, owner secret original screenplay, account token or browser-profile data in prompts/logs/public commits.

## 5. Context, batch scheduling and refusal handling

- Check \`script_revision\`, immutable source path/SHA, \`shot_id\`, \`visible_cast\`, \`speaking_cast\`, \`location_id\` and \`story_time\` BEFORE adding a task. A failed source gate cannot be fixed by asking Muse to reinterpret history.
- For re-numbered/re-written EP001, never reuse a stale \`task.thread\`. Send each new revised shot as a fresh isolated Muse chat with the current revision stated explicitly; use the **same thread** only to continue a still/video action that is genuinely based on the same approved reference and revision. A new chat cannot guarantee the service has no memory of older context, so reject contradictory responses.
- HaoHao queuing does not certify cast, rights or visual continuity. Stage a pilot of 3–5 diverse shots, inspect generated media and provenance receipts; only scale approved cases. Pause the queue if failed-shot rate grows or account flags moderation.
- Respect provider account, quota, billing, regional access and usage limits. No parallel account/rotation behavior intended to evade limits or moderation. No automated retries after a content/safety refusal. On technical network error, use bounded backoff consistent with platform rules.
- Retry taxonomy: \`CONTEXT_CONFLICT\` (fresh revision context), \`FACE_DRIFT\` (anchor audit), \`SCENE_TOPOLOGY\` (location plate), \`WRONG_CAST\` (active tags/attachments), \`VOICE_AGE_OR_WORDS\` (speaker + ASR), \`LIPSYNC\` (separate voice/viseme), \`MOTION_STIFF\` (rewrite one physical beat), \`SAFETY_BLOCK\` (human policy review), \`QUOTA_OR_TECH\` (service handling), \`NATIVE_RESOLUTION_LIMIT\` (honest upscale). Change one causal variable at a time, record attempt and reason; don't repeatedly blast the same prompt.

## 6. Provider account safety — SEMANTIC GATE, NOT a secret ban-word list

There is **no verified exhaustive list of words that causes Muse account bans**. Enforcement is based on content/context and current terms, sometimes also media inputs, outputs or behavior. Never promise “ban-proof” text, disguise prohibited intent, apply homographs/obfuscation to evade moderation, or ask Muse to disable safety filters.

For Bell & Leaf, preflight the **script+prompt+attached images+audio request+account behavior**:

- **Allowed creative scope:** original, family-friendly fantasy drama, harmless magic, sincere emotions, non-graphic danger and rescue, supportive relationships, age-appropriate adventure. A Veylora magical disruption can be depicted using shaking bells, flickering light, drifting petals, safe running, smoke-like magical mist, distance and fear on faces **without explicit bodily harm**.
- **BLOCK and rewrite the *scene itself* if necessary:** sexualized depictions of minors; explicit injury/gore, torture, cruelty or fetishized harm; extremist glorification; hateful slurs/harassment; instructions for real violence, weapons or unlawful conduct; impersonation/deepfake or cloning an identifiable real person's face/voice without rights; illegal/restricted content; evasion of moderation/usage limits; copyrighted character facsimiles. Rights and depiction risk are contextual, not single-keyword tests.
- **REVIEW rather than erase blindly:** story-critical disaster, scared children, magical battles, darkness or cries for help can be safe in a clearly non-graphic original-family-story framing. Rewrite literal actions to make the nonviolent intent truthful, not merely replace words with euphemisms to bypass policies.
- Use concrete positive directions: “A family-safe magical tremor, distant bell glow fades, no injuries depicted; focus on protective reaction, rescue and hope”; avoid inserting extraneous sensational details. Do not add risky content for a clickbait hook.
- **On content refusal:** stop attempts, log only relevant safe metadata, consult the current actual service terms/help/support, and make a bona fide content revision only if the underlying requested scene can become policy-compliant. Escalate unclear cases; don't iterate near-identical prompts to probe boundaries.
- Validate voice/image licensing separately: open-source software license ≠ model weight license ≠ commercial rights for a real person's voice.
- YouTube audience designation and monetization claims are separate compliance decisions. Don't assert RPM, Made-for-Kids status or policy immunity from this skill.

## 7. Delivery/QC — no false PASS

For each real file: save \`shot_id, screenplay_revision, prompt_sha256, original_reference_sha256[], attachment_count, thread_id, Muse output file/SHA, input_voice_plan, native_codec_fps_resolution_duration_audio, audio_conversion_sha, transcript, ASR mismatches, reference_frame comparison, human reviewer, QC verdict\`.

**Technical:** \`ffprobe\` actual MP4. 10.00 seconds nominal; valid 16:9; 24fps; audio stream expected when a speaking/sounding scene is requested; picture dimensions truthful. 1280×720 sample is only 720p, even if upscaled to 3840×2160. A 10s/24fps clip nominally contains 240 frames; confirm actual frame count if claiming 240. Record deviations, don't manufacture a PASS.

**Visual:** source vs frames at start, 2s, 5s, 8s, 9.7s AND inspect actual continuous video. Check identity/age, Bubu tail, Bix bell rule, gestures/grounded hand contact, lighting, outfit and matched architecture, eye lines, real 3D character animation (not zooming a still), no offscreen actors suddenly entering. A SHA match proves file identity, not semantic likeness.

**Sound:** listen whole clip, transcribe with ASR, compare exact A2 lines and proper nouns, measure timing/pace, check that speaking mouth is visible and movements align perceptually at each syllable. Spoken mood may vary, speaker timbre/persona may not. Do not use an ASR score alone as lip-sync certification.

**Subtitles:** generate SRT/VTT *from the accepted final speech audio*, burn/render in edit stage only, 1–2 lines, safe-margin bottom center, high-contrast white/soft outline, timed, no subtitle appearance during silence, no overlapping mouth/critical action.

**Final statuses:** \`HOLD_SOURCE\`, \`HOLD_REFERENCE\`, \`HOLD_DIALOGUE\`, \`HOLD_POLICY\`, \`HOLD_TECH\`, \`RENDERED_UNREVIEWED\`, \`QC_REJECT\`, \`QC_APPROVED\`. \`task.status=succeeded\` from HaoHao means a file was returned, **never** \`QC_APPROVED\`. Release and mass production require genuine media review and the owner's commercial/voice consent rights evidence.
